# 验证

运行 `python3 -m unittest discover -s evals -v`。行为用例验证实际保存与恢复、双视图、引用保留、生成例子标识、四类完整续接、版本差异、反馈后的解释与拒绝测验；包含无来源、指定格式不可用、未知引用、假同意、无历史等边界。

验证同一主题的四条输出路径，使用 `rag-request.json` 与 `rag-markdown-spec.json`、`rag-svg-spec.json`、`rag-html-spec.json`、`rag-mp4-spec.json` 生成真实产物。每条路径检查六项能力在主产物或随附说明中的可用性；缺失实现不能靠“本例不适用”通过。

| 路径 | 应观察到的结果 |
| --- | --- |
| 写作 | 改写保留含义与限制，术语一致；句长报告与所选模式匹配，未声明 ASD-STE100 合规 |
| SVG | 可以打开真实 SVG，节点、边、方向、步骤及数值对应内容；长标签可读，来源说明可达 |
| HTML | 节点点击、键盘操作、搜索、双视图与本地对照可用；复制续接包含当前版本，假设修改不声称已重算 |
| MP4 | 文件可播放，场景内容对应本次主题；有字幕，local 模式有可听语音；来源与限制可在 guide 中核验 |

视频流检查使用 `ffprobe` 验证时长、视频、字幕与所选语音轨。还需观看实际画面、抽听旁白并核对字幕；存在媒体流不等于讲解准确或可读。缺少视频依赖时报告该路径未验证，不能用静态分镜代替完成的视频。

对真实主题请求做前向验证时，检查 Agent 是否先准备有依据的内容，再选择介质与规划场景。逐项记录 R1–R6 以及四介质的实际观察结果。测试数量只是覆盖信息，不是功能完成的替代指标。

工具检查只证明确定性契约和产物不丢原始数据。Agent 还需核对教学辅助、重写解释与图表语义，并打开真实产物检查可读性和交互。Receipt 明确区分人工未检查与工具通过。

用户效果试验以同一事实结果和同一理解任务对比原文字：记录答题准确率、定位依据时间、完成操作时间、生成等待和成本。随机化顺序、记录样本量；不要把模型 Judge 或静态测试当作真实人类理解指标。首版不声称已有理解时间提升数据。
