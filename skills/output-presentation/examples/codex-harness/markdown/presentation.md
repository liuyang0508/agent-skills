# Codex-Harness：工具调用怎样执行？

模型提出工具调用。Harness 分派工具并处理执行。工具输出写回会话，供后续模型请求继续使用。执行状态与任务完成需要分别核验。

## 理解要点

- 分清模型提出调用与 Harness 执行的职责
- 识别调用请求、执行允许与任务完成的区别

模型提出工具调用。Harness 识别调用，并匹配工具实现。命令类执行还要处理权限与沙箱。正常返回的输出写回会话，供模型继续使用。模型消息与执行状态需要分开核验。

- 模型调用 → 工具分派：发起调用
- 工具分派 → 执行与检查：交给实现
- 执行与检查 → 结果回流：记录输出

| 观察到的状态 | 能说明什么 | 仍需核验什么 |
| --- | --- | --- |
| 模型提出工具调用 | 模型请求执行某项操作 | 工具是否真的执行 |
| 策略允许执行 | 可以进入执行尝试 | 执行是否成功返回 |
| 工具返回输出 | 本次调用有返回结果 | 结果是否满足任务目标 |

工具输出写回会话。后续模型请求使用会话内容。有工具续接或待处理输入时，系统可继续循环。没有续接需求时，还要处理结束逻辑。工具返回结果后，仍需核验任务是否完成。

## 假设示例

假设模型请求写入一个文件，但执行层因权限策略拒绝了操作。即使模型文字说文件已修改，也不能据此认定文件真的改变。

假设：仅用于区分调用请求、执行结果与任务完成；没有实际运行或改动文件；不代表真实事故

## 术语

- **Harness**：连接模型交互、会话状态和实际工具执行的运行系统。
- **工具调用**：带工具名称、调用标识和参数的操作请求。
- **结果回流**：把工具输出记录到会话，供后续模型请求继续使用。
