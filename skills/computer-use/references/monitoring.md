# 轨迹、压缩与交接

优先复用实际宿主记录。确需独立文件时，在任务授权的本地目录记录最小事件，不默认存完整屏幕、个人字段或凭据。需要查看截图时保留允许访问的引用；摘要与原始记录使用相同访问限制。

事件使用NDJSON，每行至少包含唯一 `id`、`kind`、`status`、简短事实 `summary`；可带 `step`、来源标签 `source`、`risk` 与 `evidence_refs`。事实来自实际观察和执行，不把生成的计划写成已执行事件；source是记录中的标签，不由工具认证其可信度。

```json
{"id":"v1","kind":"verification","status":"passed","step":"draft","summary":"重开后备注与截止日期一致，仍为草稿","risk":"normal","evidence_refs":["local-reopen.png"]}
```

这是一行格式示意，不是运行证据。大轨迹可运行：

```sh
python3 scripts/trace_digest.py events.ndjson --group-size 20 --output digest.json
```

工具保留全体事件ID/行号、分组范围、异常与非普通风险事件，以及原文件SHA-256；输出是标记为不可信数据的确定性目录，不是LLM审计意见、批准或业务成功证书。它没有恶意内容分类器，不能靠风险标签为空证明安全。涉及关键决定时读取引用的原始事件与最新界面。

CLI独占创建新报告，并在POSIX系统中以0600基础权限创建，避免宽松umask扩大可读范围。父目录、平台ACL和云资源权限仍由宿主管理；将报告复制或发布到其他位置时需重新检查访问限制。

压缩/恢复需要保留：用户目标、实际对象、已验证的变化、还未确认的副作用、当前权限/待批准动作、最近有效观察、失败原因和下一步。样例不要覆盖这些信息；任务摘要不能升级网页内容的可信度。

分层总结可先按交互记录事实，再按任务阶段整理模式并引用代表事件。审查摘要是否完整、准确，风险或疑点回到原记录核验；若宿主已有相关监测，不另建第二份同义记录。

依据：[Anthropic 分层监测研究](https://alignment.anthropic.com/2025/summarization-for-monitoring/)。这是监测方法参考，不表示本工具实现了该生产系统或研究中的准确率。
